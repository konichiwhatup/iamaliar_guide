## 1. このサイトの全体像

### 1.1 何のサイトか

「I AM A LIAR」というブランドの公式サイト。コンセプトに沿った商品(Collection)とブランドストーリーや読み物(Journal)を発信する、コンテンツ寄りのブランドサイト。現状は EC 機能はなく、商品紹介と問い合わせ導線まで。日本語/英語の2言語対応。

### 1.2 公開URL

- 本番: https://iamaliar.com
- Cloudflare 内部の URL: https://iamaliar.pages.dev (常に最新の本番ビルドが見える)

### 1.3 構成図(リクエストの流れ)

```
ユーザー → Cloudflare のエッジサーバー(最寄り拠点)
        → Pages 上の Next.js
        → Sanity API(コンテンツ取得)
        → HTML 配信
```

ページのコード/UI は Cloudflare、テキストや画像などのコンテンツは Sanity に分かれている。

## 2. コンテンツの更新(日常運用)

### 2.1 Sanity Studio へのアクセス

https://www.sanity.io/manage/project/22x23c52 から Studio に入れる。ローカルで起動した Studio がある場合はそちらで編集してもよい(同じデータベースに繋がる)。

### 2.2 商品(Product)の追加・編集

- Sanity Studio → Product → 「Create」で新規作成
- 入力項目: タイトル / スラッグ / カテゴリ / ステータス / 説明 / ストーリー / 素材 / 価格 / サイズ / 代表画像(featuredImage) / ギャラリー画像 / 公開日
- 「Publish」を押すまで本番には出ない。Draft のまま保存しておけば下書き状態。
- 削除する場合は対象ドキュメントを開いて右上「Delete」

### 2.3 記事(Journal)の追加・編集

- Sanity Studio → Journal → Create
- 入力項目: タイトル / スラッグ / 抜粋 / カテゴリ / タグ / カバー画像 / 本文(リッチテキスト)/ 関連商品 / 著者 / 公開日
- 関連商品(relatedProducts)を指定すると、記事ページから商品ページへの導線が出る

### 2.4 ホームのヒーロー画像・キャッチを変える

Sanity Studio → Home Hero(シングルトン)を開く。`heroImage`(画像)/ `heroCaption`(キャッチコピー)/ `heroImageOpacity`(画像の不透明度)/ `heroLink`(リンク先の商品)を編集して Publish。

### 2.5 公開・非公開の切り替え

- **公開する:** Studio で「Publish」ボタン
- **非公開に戻す:** Publish 済みドキュメントを開いて「Unpublish」
- **完全に消す:** 「Delete」(ただし戻せないので注意)

### 2.6 反映までの時間

本番では Sanity の CDN が最大60秒キャッシュするため、Publish 直後は反映に数十秒〜1分ほどかかることがある。また Cloudflare 側のページ HTML キャッシュにより、初回アクセスでは古いまま見える場合がある。確実に最新を見たい場合はブラウザのスーパーリロード(`Cmd+Shift+R`)を使う。

### 2.7 画像のアップロード

- 推奨形式: JPEG または WebP(写真)/ PNG(図やロゴなど透過が必要な場合)
- 推奨サイズ: 横幅 2000px 程度。Sanity 側で自動的にリサイズ・最適化される。
- ファイル名は英数字推奨(日本語ファイル名は避ける)

## 3. デプロイと公開

### 3.1 通常のデプロイ(自動)

コードを変更して GitHub の main ブランチに push すると、Cloudflare Pages が自動的にビルド・デプロイする。ローカルから手で何かする必要はない。

```
流れ: コード編集 → git add / commit → git push origin main → CF Pages 検知 → ビルド → 本番反映(2〜5分)
```

### 3.2 デプロイの状況確認

Cloudflare ダッシュボード → Workers & Pages → iamaliar → Deployments タブ。最新のビルドが緑(Success)なら成功、赤(Failed)なら失敗。ビルドログをクリックすると詳細が見られる。

### 3.3 ビルドが失敗したとき

- Deployments の Failed をクリックしてログを見る
- よくある原因: TypeScript の型エラー / Next.js の build エラー / 依存関係の install 失敗
- ローカルで `npm run build` を実行して同じエラーが出るか確認
- 修正コミット → push し直すと自動で再ビルドされる

### 3.4 ロールバック(以前の状態に戻す)

Deployments タブで以前の成功したビルドを選び、「Rollback to this deployment」をクリックすると数秒で戻る。GitHub 側の main ブランチは触らないので、コードの修正と並行しても問題ない。

### 3.5 緊急で手動デプロイする

GitHub 連携が何らかの理由で動かない時の代替手段。

```bash
npm run deploy
```

内部的には next-on-pages でビルドし、`wrangler pages deploy` で直接 CF にアップロードする。

## 4. ドメイン・DNS

### 4.1 現在の設定

| 項目 | 内容 |
|------|------|
| ドメイン | iamaliar.com (apex のみ) |
| 登録先 | Cloudflare Registrar |
| DNS | Cloudflare 内で完結(CNAME flattening で apex を Pages に向けている) |
| www | 未設定(必要なら Custom domains に追加) |

### 4.2 ドメインの更新

Cloudflare Registrar の自動更新がデフォルトで有効。期限が近づくとメール通知が来る。クレジットカードの有効期限切れに注意。

更新確認場所: Cloudflare ダッシュボード → 上部メニューのアカウント名 → Domain Registration → Manage Domains

### 4.3 DNS レコードを触る時の注意

- Pages 用の自動レコード(`iamaliar.com` の A や CNAME)は触らない。削除すると即サイトが落ちる。
- メール用(MX / TXT)を後から追加するのは安全。
- 変更前に既存レコードのスクショを残す習慣をつけると安心。

### 4.4 SSL 証明書

Cloudflare が Google Trust Services 経由で自動発行・自動更新(3ヶ月ごと)。基本ノータッチ。ブラウザで「保護されていない通信」と出たら、まず Pages の Custom domains で当該ドメインのステータスを確認する。

### 4.5 メール用 DNS を追加したい場合

Google Workspace や Resend などを使う場合は、各サービスから指定された MX / TXT(SPF, DKIM, DMARC)レコードを Cloudflare の DNS に追加する。既存の Pages 用レコードとは衝突しない。

## 5. モニタリング

### 5.1 アクセス数を見る

Cloudflare ダッシュボード → Web Analytics、または Workers & Pages → iamaliar → Metrics。Cookie 不要・GDPR 対応・無料。リクエスト数 / ユニーク訪問者 / 国別 / リファラ / ページ別アクセスが見られる。

### 5.2 エラー率を見る

Workers & Pages → iamaliar → Metrics タブ。ステータスコード分布(2xx / 3xx / 4xx / 5xx)を確認。5xx が継続的に出ていたら障害の可能性。

### 5.3 リアルタイムでログを追う

ターミナルから以下を実行:

```bash
npx wrangler pages deployment tail --project-name=iamaliar
```

リクエストごとの URL / ステータス / エラー内容が流れる。デバッグ中だけ使う。

### 5.4 攻撃を疑うとき

Cloudflare ダッシュボード → Security Center(または Security → Events)。WAF にブロックされたリクエストや不審なアクセス元を確認できる。Free プランでは詳細イベントが制限される場合あり。

### 5.5 推奨ルーティン

- **毎日:** 特になし(問題があればメールで通知が来る)
- **週1:** Web Analytics でトラフィック傾向、Metrics で 5xx 発生有無
- **月1:** Sanity の使用容量、Cloudflare の請求金額、ドメインの有効期限

## 6. トラブル対応

### 6.1 サイトが開かない

- https://iamaliar.pages.dev で開けるか確認 → 開けるなら DNS / Custom domain の問題
- Pages 側でも開けないなら直近のデプロイを確認 → 失敗していたらロールバック
- Cloudflare 全体障害の可能性: https://www.cloudflarestatus.com/ を確認

### 6.2 画像が表示されない

- 画像 URL を直接ブラウザで開いて 404 か確認
- Sanity Studio で対象ドキュメントの画像が削除されていないか確認
- CSP(コンテンツセキュリティポリシー)で `cdn.sanity.io` と `images.unsplash.com` 以外の画像はブロックされる仕様。新しい画像ホストを使うなら `next.config.ts` の `img-src` に追加が必要

### 6.3 Sanity で編集したのに反映されない

- 「Publish」ボタンを押しているか確認(保存だけだと Draft のまま)
- Sanity の CDN キャッシュ(最大60秒)を待つ
- ブラウザのスーパーリロード(`Cmd+Shift+R`)
- それでも反映されない場合は CF Pages の Deployments で再デプロイ

### 6.4 ビルドが落ちる

- ローカルで `npm run build` を実行しエラーを再現
- TypeScript の型エラー: `src/types/product.ts` と実際のデータの食い違いを確認
- 依存関係の問題: `package-lock.json` を削除して `npm install` をやり直す
- `.npmrc` の `legacy-peer-deps=true` は CI 通過のために必要(消さない)

### 6.5 SSL エラー / 証明書警告

- Custom domains で対象ドメインのステータスを確認 → Active でなければ再アクティベート
- 発行直後は反映に時間がかかる(最大15分)
- 新規追加直後の場合、Cloudflare の Universal SSL の発行待ち

GitHub にすべて入っているので、リポジトリをクローンできれば復元可能。手元のローカルも実質バックアップになっている。

### 9.2 Sanity のコンテンツ


- **ドメイン** → 他社レジストラに移管可能。50日以内の更新後は移管不可なので注意。

## 10. よくある作業手順(チートシート)

### 10.1 新商品を追加する

1. Sanity Studio を開く
2. Product → Create
3. 画像・テキスト・価格などを入力
4. Publish ボタンを押す
5. 1分ほど待って `iamaliar.com/collection` で表示確認

### 10.2 ヒーロー画像を差し替える

1. Sanity Studio → Home Hero を開く
2. heroImage を新しい画像に差し替え
3. 必要なら heroCaption / heroImageOpacity を調整
4. Publish

### 10.3 サイトを一時的に止めたい

正式なメンテナンスモードはないが、緊急時は次の手段がある:

- Cloudflare ダッシュボード → DNS でメインの A/CNAME を一時的にプロキシオフにする(おすすめしない)
- Pages の Deployments から「Pause Deployments」で新規デプロイを止める
- Custom domain を一時的に外す(復帰に時間がかかるので最終手段)

### 10.4 翻訳テキストを修正する

UI のラベル(ナビ・フッター・ボタン文言など)はコード内に直書きされている。ファイル: `src/lib/i18n.ts`。`ja` / `en` それぞれの translations オブジェクトを編集してコミット → push。

## 11. 付録

### 11.1 用語集

| 用語 | 説明 |
|------|------|
| apex(エイペックス) | ドメインの最上位。`iamaliar.com` のように何も付かない裸ドメイン。 |
| CNAME | ドメイン → 別のドメインを指す DNS レコード。エイリアスのこと。 |
| CNAME flattening | apex に CNAME を張れない仕様を Cloudflare が裏で A レコードとして解決する仕組み。 |
| CDN | Content Delivery Network。世界中に複製を置いて、ユーザーに近い拠点から配信する仕組み。 |
| CSP | Content Security Policy。読み込めるリソースを HTTP ヘッダで制限するセキュリティ機能。 |
| HSTS | HTTP Strict Transport Security。ブラウザに HTTPS のみを使わせる宣言。 |
| GROQ | Sanity が使う独自クエリ言語。GraphQL 的な役割。 |
| next-on-pages | Next.js を Cloudflare Pages で動かすためのアダプタ。 |
