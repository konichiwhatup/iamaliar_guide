### 1.3 構成図(リクエストの流れ)

```
ユーザー → Cloudflare のエッジサーバー(最寄り拠点)
        → middleware(セキュリティヘッダー付与)
        → Pages 上の Next.js(Edge Runtime、毎回サーバーで描画)
        → Sanity API(CDN 経由でコンテンツ取得)
        → HTML 配信
```

ページのコード/UI は Cloudflare、作品・ニュース・ヒーロー画像は Sanity に分かれている。

### 2.5 公開・非公開の切り替え

- **公開する:** Studio で「Publish」ボタン
- **非公開に戻す:** 右上「…」メニュー →「Unpublish」(公開中のドキュメントでのみ選べる)
- **完全に消す:** 「…」→「Delete」(戻せないので注意)

> Studio は `CustomLayout.tsx` で **ドキュメント上部の Published / Draft ピルと右上の Perspective ドロップダウンを CSS で非表示**にしている。また `sanity.config.ts` で **Releases を無効化**しているため、予約公開(Schedule)やリリース機能は使わない前提(商品スキーマの説明文にも「現在のプランでは Scheduled Publishing は利用できない」と明記)。状態は左の一覧のドット(状態インジケーター)で判断する。

### 2.6 反映までの時間

- 全ページ `force-dynamic` + Edge Runtime で、**HTML は毎回サーバーで生成**される(`cf-cache-status: DYNAMIC`)。Cloudflare 側に HTML のキャッシュは無い
- 本番の Sanity クライアントは `useCdn: true`。**Sanity の API CDN に最大60秒程度のキャッシュ**があるので、Publish 直後は数十秒〜1分ほど古い内容が出ることがある
- 1〜2分待っても変わらなければブラウザのスーパーリロード(`Cmd+Shift+R`)
- 開発環境(`npm run dev`)では CDN もキャッシュも使わず即時反映

### 2.7 画像のアップロード

- 推奨形式: JPEG または WebP(写真)/ PNG(透過が必要な場合)
- 推奨サイズ: 横幅 1500〜2500px 程度。5MB 以内目安
- ファイル名は英数字推奨(日本語ファイル名は避ける)
- `next.config.ts` で `images.unoptimized: true` のため、**Next.js 側でのリサイズはしていない**。アップロードした元画像(`cdn.sanity.io` の原寸 URL)がそのまま配信される。重い画像はそのまま表示速度に響くので、アップ前に軽くしておく

## 3. デプロイと公開

### 3.1 通常のデプロイ(自動)

コードを変更して GitHub の main ブランチに push すると、Cloudflare Pages が自動的にビルド・デプロイする。

```
流れ: コード編集 → git add / commit → git push origin main → CF Pages 検知 → ビルド → 本番反映(2〜5分)
```

ビルド設定(Cloudflare Pages):

| 項目 | 値 |
|---|---|
| Build command | `npx @cloudflare/next-on-pages`(= `npm run pages:build`) |
| Output directory | `.vercel/output/static` |
| 互換フラグ | `nodejs_compat`(`wrangler.toml`) |

### 3.2 デプロイの状況確認

Cloudflare ダッシュボード → Workers & Pages → iamaliar → Deployments タブ。緑(Success)なら成功、赤(Failed)なら失敗。ビルドログをクリックすると詳細が見られる。

### 3.3 ビルドが失敗したとき

- Deployments の Failed をクリックしてログを見る
- よくある原因: TypeScript の型エラー / Next.js の build エラー / 依存関係の install 失敗 / ページに `export const runtime = "edge"` が無い(next-on-pages は動的ページすべてに Edge Runtime を要求する)
- ローカルで `npm run build`、さらに `npm run pages:build` を実行して同じエラーが出るか確認
- 修正コミット → push し直すと自動で再ビルドされる

### 3.4 ロールバック(以前の状態に戻す)

Deployments タブで以前の成功したビルドを選び、「Rollback to this deployment」をクリックすると数秒で戻る。GitHub の main は変わらないので、次に push すると最新コードで上書きされる点に注意。

### 3.5 緊急で手動デプロイする

GitHub 連携が何らかの理由で動かない時の代替手段。

```bash
npm run deploy
```

内部的には `next-on-pages` でビルドし、`wrangler pages deploy` で直接 CF にアップロードする。

### 3.6 Sanity Studio のデプロイ(スキーマを変えたとき)

Studio はサイトとは**別にデプロイ**する。スキーマ(`iamaliar/schemaTypes/`)や `sanity.config.ts` を変えたら:

```bash
cd iamaliar
npm install
npm run deploy      # = sanity deploy
```

- サイト(main への push)だけでは Studio の項目は変わらない
- Studio は `autoUpdates: true`(Sanity 本体のバージョンは自動更新)
- スキーマから項目を消しても、**Sanity に保存済みのデータは消えない**(画面に出なくなるだけ)

### 4.1 現在の設定

| 項目 | 内容 |
|------|------|
| ドメイン | iamaliar.com / www.iamaliar.com(どちらも表示される) |
| 登録先 | Cloudflare Registrar |
| DNS | Cloudflare 内で完結(apex は CNAME flattening で Pages に向けている) |

> www は 2026-11 時点で 200 を返すことを確認済み(Pages の Custom domains に追加されていると思われる)。リダイレクトではなく同じページをそのまま表示している。

### 4.2 ドメインの更新

Cloudflare Registrar の自動更新がデフォルトで有効。期限が近づくとメール通知が来る。クレジットカードの有効期限切れに注意。

更新確認場所: Cloudflare ダッシュボード → Domain Registration → Manage Domains

### 4.3 DNS レコードを触る時の注意

- Pages 用のレコード(`iamaliar.com` / `www` の CNAME)は触らない。削除すると即サイトが落ちる。
- メール用(MX / TXT)を後から追加するのは安全。
- 変更前に既存レコードのスクショを残す習慣をつけると安心。

### 4.4 SSL 証明書

Cloudflare が自動発行・自動更新。基本ノータッチ。ブラウザで「保護されていない通信」と出たら、まず Pages の Custom domains で当該ドメインのステータスを確認する。

### 4.5 メール用 DNS を追加したい場合

Google Workspace や Resend などを使う場合は、各サービスから指定された MX / TXT(SPF, DKIM, DMARC)レコードを Cloudflare の DNS に追加する。既存の Pages 用レコードとは衝突しない。

## 5. モニタリング

### 5.1 アクセス数を見る

Cloudflare ダッシュボード → Web Analytics、または Workers & Pages → iamaliar → Metrics。Cookie 不要・無料。リクエスト数 / ユニーク訪問者 / 国別 / リファラ / ページ別アクセスが見られる。CSP で `static.cloudflareinsights.com` を許可済み。

### 5.2 エラー率を見る

Workers & Pages → iamaliar → Metrics タブ。ステータスコード分布(2xx / 3xx / 4xx / 5xx)を確認。5xx が継続的に出ていたら障害の可能性。旧 URL(`/collection` `/journal`)への 404 がしばらく出るのは想定内。

### 5.3 リアルタイムでログを追う

```bash
npx wrangler pages deployment tail --project-name=iamaliar
```

リクエストごとの URL / ステータス / エラー内容が流れる。デバッグ中だけ使う。

### 5.4 攻撃を疑うとき

Cloudflare ダッシュボード → Security → Events。WAF にブロックされたリクエストや不審なアクセス元を確認できる。Free プランでは詳細イベントが制限される場合あり。

### 5.5 推奨ルーティン

- **毎日:** 特になし(問題があればメールで通知が来る)
- **週1:** Web Analytics でトラフィック傾向、Metrics で 5xx 発生有無
- **月1:** Sanity の使用量、Cloudflare の請求、ドメインの有効期限、Sanity データのバックアップ(9.2)
- **随時:** GitHub の Dependabot アラート(依存関係の脆弱性)

## 6. トラブル対応

### 6.1 サイトが開かない

- https://iamaliar.pages.dev で開けるか確認 → 開けるなら DNS / Custom domain の問題
- Pages 側でも開けないなら直近のデプロイを確認 → 失敗していたらロールバック
- Cloudflare 全体障害の可能性: https://www.cloudflarestatus.com/ を確認

### 6.2 画像が表示されない

- 画像 URL を直接ブラウザで開いて 404 か確認
- Sanity Studio で対象ドキュメントの画像が削除されていないか確認
- CSP(`src/middleware.ts` の `img-src`)で **`cdn.sanity.io` と `images.unsplash.com` 以外の画像はブロック**される。新しい画像ホストを使うなら middleware の `img-src` と `next.config.ts` の `remotePatterns` の両方に追加

### 6.3 Sanity で編集したのに反映されない

- 「Publish」を押しているか確認(保存だけだと Draft のまま)
- Sanity の CDN キャッシュ(最大60秒程度)を待つ
- ブラウザのスーパーリロード(`Cmd+Shift+R`)
- **ニュース本文の見出し・太字・画像が出ない** → 仕様(2.3 参照)。不具合ではない
- **項目自体を足したのにサイトに出ない** → スキーマに足しただけでは出ない。`queries.ts` と各ページのコードにも表示処理が必要

### 6.4 ビルドが落ちる

- ローカルで `npm run build` を実行しエラーを再現
- TypeScript の型エラー: `src/types/product.ts` と実際のデータの食い違いを確認
- 依存関係の問題: `package-lock.json` を削除して `npm install` をやり直す
- `.npmrc` の `legacy-peer-deps=true` は CI 通過のために必要(消さない)
- Sanity Studio(`iamaliar/`)は Next.js のビルド対象外(`tsconfig` で除外)。Studio の型エラーはサイトのビルドに影響しない

### 6.5 画面が真っ白 / スクリプトが動かない

- ブラウザの開発者ツール → Console に「Content Security Policy」違反が出ていないか確認
- `middleware.ts` が毎リクエスト nonce を発行し、Next.js が自分のインラインスクリプトにそれを付与する仕組み。外部スクリプト(分析タグ等)を追加するなら `script-src` にドメインを追加する
- middleware を消したり matcher を変えたりすると nonce が渡らずスクリプトがブロックされることがある(2026-11-07 に一度発生 → `8dc9d31` で修正)

### 6.6 SSL エラー / 証明書警告

- Custom domains で対象ドメインのステータスを確認 → Active でなければ再アクティベート
- 発行直後は反映に時間がかかる(最大15分)

```bash
npx sanity@latest dataset export productionenabled backup-$(date +%Y%m%d).tar.gz
```

月1回これを実行してファイルを保存しておくと安心。tar.gz には全ドキュメントと画像が含まれる。

### 9.3 万一サービスが終了する場合

- **Sanity 終了** → 上記エクスポートで救出。別 Headless CMS への移行は要工数だが可能。
- **Cloudflare 終了** → next-on-pages を外し、Vercel など別ホストに移す。
- **ドメイン** → 他社レジストラに移管可能。

## 10. よくある作業手順(チートシート)

### 10.1 新しい作品を追加する

1. Sanity Studio → 商品 → 新規作成
2. 題名・説明文・ステータス・メイン画像(必須)を入力。Slug は「Generate」
3. Publish
4. 1分ほど待って `iamaliar.com/gallery` で表示確認

### 10.2 ヒーロー画像を差し替える

1. Sanity Studio → ホーム画面ヒーロー
2. ヒーロー画像を差し替え、必要ならキャプション / 不透明度 / リンク先を調整
3. Publish

### 10.3 サイトを一時的に止めたい

→ [一時停止ガイド]({{ "/maintenance/" | relative_url }}) を参照。

### 10.4 サイト上の文言を修正する

Sanity で管理していない文章は、すべて `src/lib/i18n.ts` にある。`ja` と `en` の2ブロックがあるので**両方**を直す。

| 直したいもの | `i18n.ts` のキー |
|---|---|
| メニュー名 | `nav` |
| フッターのタグライン | `footer.tagline` |
| ホームのタグライン「解釈はあなたが決めてください。」 | `home.heroTagline` |
| Brand Story の見出しと5章 | `home.brandStoryHeading` / `home.sections` |
| Gallery の説明文・準備中テキスト | `gallery` |
| 価格欄の文言(PRICELESS. / 問い合わせ文言) | `product.priceLabel` / `product.inquireLine` / `product.priceNote`(¥ と白いバーは `GalleryClient.tsx` と `ProductDetailClient.tsx` に直書き) |
| ステータスの表示名 | `product.status` |
| Philosophy(導入・Q&A・締め) | `philosophy.intro` / `philosophy.qa` / `philosophy.closing` |
| Contact の見出し・案内・ボタン文言 | `contact` |
| FAQ | `contact.faq.items`(`{ q, a }` を足せば増える) |
| 404 の文言 | `notFound` |

本文中の `\n\n`(空行)が段落の区切り、`\n`(改行1つ)は Philosophy では行内改行になる。

編集 → `npm run dev` で確認 → commit → push。

### 10.5 LINE / Instagram のリンク先を変える

URL がファイルごとに直書きされているので、すべて置き換える:

```bash
grep -rn "lin.ee" src/
grep -rn "instagram.com" src/
```

| URL | 使っているファイル |
|---|---|
| LINE `https://lin.ee/o94I6DM` | `src/app/HomeClient.tsx`(未使用定数)/ `gallery/GalleryClient.tsx` / `gallery/[slug]/ProductDetailClient.tsx` / `contact/ContactClient.tsx` |
| Instagram `https://www.instagram.com/watashi_wa_usotsuki_desu/` | `contact/ContactClient.tsx` |

### 10.6 古い URL(/collection, /journal)をリダイレクトしたい

現在は 404。必要なら Cloudflare ダッシュボード → iamaliar.com → Rules → Redirect Rules で `/collection*` → `/gallery` を設定する(コード変更不要)。

## 11. 付録

### 11.1 用語集

| 用語 | 説明 |
|------|------|
| apex | ドメインの最上位。`iamaliar.com` のように何も付かない裸ドメイン。 |
| CNAME | ドメイン → 別のドメインを指す DNS レコード。 |
| CNAME flattening | apex に CNAME を張れない仕様を Cloudflare が裏で A レコードとして解決する仕組み。 |
| CDN | 世界中に複製を置いて、ユーザーに近い拠点から配信する仕組み。 |
| CSP | Content Security Policy。読み込めるリソースを HTTP ヘッダで制限するセキュリティ機能。 |
| nonce | リクエストごとに使い捨てる乱数。CSP で「このスクリプトだけ実行してよい」と示すのに使う。 |
| HSTS | ブラウザに HTTPS のみを使わせる宣言。 |
| GROQ | Sanity が使う独自クエリ言語。 |
| Edge Runtime | Cloudflare のエッジで動く軽量な実行環境。このサイトの全ページがこれで動いている。 |
| next-on-pages | Next.js を Cloudflare Pages で動かすためのアダプタ。 |
| シングルトン | 1件だけ存在する設定用ドキュメント(ここでは homeHero)。 |
